# 📞 Исправление формата телефонных номеров

## Проблема
Телефоны сохранялись в БД с форматированием `+7 (922) 367-00-81`, из-за чего:
- ❌ Пользователи не могли войти (не находился номер)
- ❌ Поиск по номеру не работал
- ❌ API сравнение не совпадало

## Решение

### 1. ✅ Обновлен код админки (`admin.js`)

**Добавлена функция очистки номера:**
```javascript
function cleanPhoneNumber(phone) {
    let cleaned = phone.replace(/\D/g, ''); // Убираем все кроме цифр
    
    if (cleaned.startsWith('8')) {
        cleaned = '7' + cleaned.substring(1);
    }
    
    if (!cleaned.startsWith('7')) {
        cleaned = '7' + cleaned;
    }
    
    return cleaned; // Возвращает: 79223670081
}
```

**Теперь номера сохраняются правильно:**
- Формат в БД: `79223670081` ✅
- Отображение в админке: `+7 (922) 367-00-81` ✅
- Работает вход: ✅

### 2. 🔧 Исправление существующих номеров

Запустите SQL скрипт `fix_phone_numbers.sql` в Supabase:

```sql
-- Убирает все символы кроме цифр
UPDATE clients
SET phone = REGEXP_REPLACE(phone, '\D', '', 'g')
WHERE phone IS NOT NULL AND phone ~ '\D';

-- Заменяет 8 на 7 в начале
UPDATE clients
SET phone = '7' || SUBSTRING(phone FROM 2)
WHERE phone LIKE '8%';

-- Добавляет 7 если нужно
UPDATE clients
SET phone = '7' || phone
WHERE phone IS NOT NULL 
  AND NOT phone LIKE '7%' 
  AND LENGTH(phone) = 10;
```

### 3. 📊 Проверка

После запуска скрипта проверьте:

```sql
SELECT 
    id,
    name,
    phone,
    LENGTH(phone) as length,
    CASE 
        WHEN LENGTH(phone) = 11 AND phone LIKE '7%' THEN 'OK'
        ELSE 'ERROR'
    END as status
FROM clients
WHERE phone IS NOT NULL
ORDER BY status DESC;
```

Все номера должны быть со статусом `OK`.

✅ **Добавление клиента** - номер очищается перед сохранением
✅ **Экстренный контакт** - также очищается
✅ **Отображение в таблице** - форматируется для красоты
✅ **Валидация** - проверка на 11 цифр
